## Правило статусов

Источник этапа — список из `model-data.js` (`stages[].status`): договоры (`contracts`), позиции лифта с заданными стадиями (`lift`), позиции этажей (`floors`).
Стадия позиции: оверлей → `status.js` → `stageHint` в `data.js`.
Этап получает **наименее продвинутую** стадию из источников (считается < заявлено < ожидание < в процессе < готово). «Готово» — только если готово всё.
Оплата договора не означает стройку: оплаченный КП лифта (`c-lift = done`) не делает этап 03 готовым, пока 6 позиций лифта ждут.

На 26.09.2026: 00 готово · **01 в процессе (сейчас)** · 02 нет данных · 03 ожидание · 04–05 считается · 06–08 ожидание · 09 считается.
По ИСХОДНЫМ §6 «сейчас» — этап 02. Чтобы модель это показала, в `data.js` нужно поставить `c-dem.stage = "done"` — это решение человека.

## Открытые вопросы (не закрыты моделью)

1. Оголовок +14.900 над кровлей +13.800 / карнизом +14.100 — нет на АС и рендерах.
2. 4-я остановка +10.200 против пола террасы +10.800.
3. Свет шахты на 2–3 этажах — нужен обмер; колонна ряда 8,6 при 400 × 400 заходит на каркас ≈45 мм.
4. Стороны А/Б к осям не привязаны; если лифт открывается в лестничный холл — повернуть на 90° (`lift.doors[].side` в `model-data.js`).
5. Площадь офиса: 185,66 (сайт) против 189,3 (план v4).
6. Надстройка АИ ≠ фасады; смета 149 / 83 м² — по АИ.
7. Сколько плит ПК реально снимается над шахтой.
